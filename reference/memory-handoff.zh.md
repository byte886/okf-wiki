# 跨会话外置记忆约定（memory-handoff）

> 解决"新对话豆包失忆"。本文件讲**项目级的重型、结构化、会复利的长期记忆**怎么用 OKF bundle 承载，以及它如何与你 `~/Doubao/AGENTS.md` 第一章的全局四层记忆机制衔接。

---

## 1. 先定位：OKF 记忆在"全局四层"里处在哪一层

你的全局 AGENTS.md 已把记忆分四层，**不要另起冲突体系**：

| 全局层 | 载体 | 装什么 | 与 OKF 的关系 |
|---|---|---|---|
| 规则层 | `~/Doubao/AGENTS.md` | 怎么干活、流程、红线（长期稳定、精简） | 不复制 OKF 内容，最多放一行"项目结构化知识用 okf-wiki 技能"的指针 |
| 事实层 | `~/Doubao/PROFILE.md` | 用户身份/偏好、**项目索引（一行一个）**、外部资源位置 | 每个 OKF 项目只在 PROFILE 留**一行指针**（项目名｜bundle 路径｜一句话状态｜更新日期），细节不进 PROFILE |
| 平台层 | 豆包自带「记忆」 | 模糊偏好，仅补充 | 与白盒冲突时以白盒为准 |
| 成品层 | 飞书知识库 / 项目文档 | 任务成品、项目内部状态 | **OKF bundle 就落在这一层的"本地侧"**：是项目内部结构化知识与记忆的本地源头，飞书是对外/成品发布侧 |

**一句话分工**：PROFILE 记"有这么个项目、它在哪"（一行指针）；项目 OKF bundle 记"这个项目内部的一切结构化知识与来龙去脉"。全局规则不膨胀，项目记忆可无限复利。

---

## 2. 项目记忆 = 一个 OKF bundle（四类件）

| OKF 件 | 在记忆里的职责 | gaodun 对应（已有体系，映射不重建） |
|---|---|---|
| **schema**（规范，教 AI 怎么读写） | 项目 `AGENTS.md`：角色、规则、读文档顺序、红线 | gaodun 根 `AGENTS.md`（已很完善，只加指针） |
| **index**（有什么、在哪） | 目录/导航页，渐进式披露入口 | `docs/DOCUMENTATION_MAP.md`、各组 `README.md` |
| **log**（最近发生了什么，倒序） | 变更时间线 | `CHANGELOG.md`、任务报告 |
| **concepts**（稳定知识，一个 md 一个知识点） | 架构、模块、决策、知识点、方法论、SOP | `knowledge-base/知识详解/*.md`、`docs/**`、ADR |
| （动态状态，易变） | 当前进度、计数、阻塞——**实时读、不抄进正文** | `project-management/active/TASK_STATUS.md` 等台账 |

> 关键：**稳定的结论进 concept（带 frontmatter），易变的状态进台账（实时读）**。进度百分比、"当前做到第几讲"、当天日期这类值一旦抄进正文就会静默过期，只在台账/frontmatter 维护，需要时现读。

## 3. 新会话恢复上下文 SOP（按顺序，省 token）

新对话打开项目后，**不要靠对话记忆猜**，按"漏斗式"逐层加载：

1. **读 schema**：项目 `AGENTS.md`（规则、角色、强制阅读顺序、红线）。
2. **读 index**：文档地图 / 根 `index.md`，只看"有什么、在哪"，先不展开正文（渐进式披露）。
3. **读 log 最近 N 条**：`CHANGELOG`/`log.md` 顶部最近几条 + 动态台账 `TASK_STATUS`（当前状态、下一步、阻塞）。
4. **按需深读 concept**：本轮任务涉及哪几个知识点，才沿 index 链接打开对应 `.md`；不整库注入。
5. **对齐信任与时效**：读到的概念看 `verified`（谁核过）与 `stale_after`（是否已过期）；过期/未核验的内容先标注，不直接当定论。

> 规模提示（区分两种"规模"，别混）：
> - **LLM 上下文规模**（本技能关心的）：约 100 篇、单篇数百 token 的量级，靠"index 定位 + 按需下钻"即可，无需向量库；再大（数百篇/数十万 token 全量塞进上下文）模型会不再细读，此时必须坚持先 index 后下钻、或加检索，不要整库灌入。
> - **浏览器图形渲染规模**（仅当未来做知识图谱可视化时才相关）：第三方实测力导向图在约 2k 节点会阻塞页面约 32 秒（成本近二次增长），>1k 应切线性布局、>5k 只渲染子树。这是渲染性能，不是上下文限制，勿混用。（数据源：okf-skills scale-guardrails，合成包/Chrome 实测，2026-07）

### 开场话术（用户视角，可复制）
- 恢复：`项目架构师，按 okf-wiki 恢复上下文：读 AGENTS、文档地图/index、CHANGELOG 最近条目和 active 台账，然后告诉我当前状态和下一步。`
- 沉淀：`按 okf-wiki 把这次结论 ingest 成 concept，更新 index 和 log，补来源、generated/verified 和 stale_after。`
- 体检：`按 okf-wiki lint 一遍：查缺 type、死链、孤儿页、过期未复审、缺来源。`

## 4. 写入（沉淀）时机与动作

任务收尾、或用户说"更新记忆/沉淀一下"时：

> **写入前三问（闸门，任一为"否"则不进 concept，只收拢下列已有规则、不另立新规）**：①换个会话还用得到吗？→ 否则只进任务日志；②是稳定结论而非会变的值吗？→ 易变值只进台账（见 §2 末、§5）；③能注明来源吗？→ 不能先标"待核"（见 §5）。

1. 判断该写哪层：跨会话仍有效的**稳定知识/决策/方法** → 新建或更新 concept；一次性过程细节 → 任务报告/日志，不进长期记忆。
2. 写 concept 用**标准档 frontmatter**：`generated.by` 记本次产出者与时间；人工确认过加 `verified: human:xxx`；给会过期的内容设 `stale_after`；来源进 `sources`。
3. **同步 index/log**：新增/改名 concept 必须在 index 登记（否则成孤儿页）；在 log 顶部当天分组追加一条 `**Creation/Update**`。
4. 易变状态只更新台账，不改成 concept 正文。
5. 在 PROFILE 的 project 区刷新该项目那**一行指针**的状态与日期（不展开细节）。
6. 写入前用一句话告知"我准备沉淀什么"，用户说不用则不写（沿用全局 AGENTS 1.2 协议）。

## 5. 防漂移、防"幻觉复利"

- **只记契约形状，不抄会变的值**：记"这个指标由某脚本/某表计算、口径是什么"，不把某天算出的具体数抄进知识库当永恒事实。
- **来源可溯**：关键结论带 `sources` 脚注；无法核实写"待核"，不编造。
- **时效可见**：政策/考季/版本强相关内容设 `stale_after`，lint 自动提醒复审，避免旧结论被反复引用。
- **人工复核抬信任等级**：重要结论请人过一眼并记 `verified: human:xxx`；AI 自产自销至多是 machine-confirmed。
- **矛盾当场裁决**：发现新旧 concept 冲突，按项目权威度规则处理并在 log 记录，不并存互相打架的结论。
- **退役不硬删**：过时概念改 `status: deprecated` 保留链接与历史（与全局 AGENTS 1.3"标退役不硬删"一致）。

## 6. 能力边界（诚实说明）

- **只有"软模式"，没有"强制钩子"**：维护自动化业界分两档——软模式（在项目 AGENTS/规则里写"任务前读 bundle、变更后回写"，靠 AI 遵循）与强制模式（IDE 的 Stop hook 在你没更新 log 时直接阻断收尾）。豆包/Trae 没有后台文件钩子，**只能做软模式**：流程约定 + 模板 + 可手动运行的校验脚本，靠项目 AGENTS 指针和开场/收尾话术触发，自动化比 IDE 型 Agent 低一档。这是平台边界，不是设计疏漏（连最成熟的 okf-skills 也把强制钩子做成默认休眠、需逐包显式开启）。
- 全局 `~/Doubao/AGENTS.md` 改动需**重启豆包**才在新对话生效（全局 AGENTS 自述）；项目 AGENTS 则随项目加载。
- **刻意不做的件（避免重复建设，不必再评估）**：
  - 不做只读 MCP 检索服务——豆包自带 Read/Grep/Glob，MCP 对有文件工具的 Agent 是重复（okf-skills 作者本人也因这点一度否决 MCP，仅为"品类对齐"才附带发布）。
  - 不做 Claude 插件 / skills.sh 分发 / GitHub Action 门控 / Stop hook——豆包无插件与钩子机制；项目要门控时，直接在本地/既有 CI 里调用 `okf_validate.py`（gaodun 已有 pre-commit，可挂 `--max-warnings`）。
  - 不做交互式知识图谱可视化（首版）；不做从 git 历史/会话记录的事件溯源重放（豆包单 Agent、知识成品多不进 git）。
  - 不做 v0.1→v0.2 的 `--migrate`（本技能从 v0.2 起步、无旧版存量）。
- 本技能不联网、不起服务、不接向量库；需要更强检索时由项目自行叠加，OKF 文件本身保持纯 Markdown、可被任意工具读取。

### 6.1 这套信任/时效字段到底有多大用？（第三方基准，别夸大）
okf-skills 自带、并公开了缺陷的小样本基准（2026-09，样本很小，**只说明方向、不是定论**）：
- 写入门控让"过期答案"降约 39 个百分点、设了 `stale_after` 到期降约 28 个百分点，但 20 个样本下两者**统计上区分不开**；没有门控时写作者有 57% 的情况根本不更新文档——这正是元数据补位的地方。
- 信任字段实验里，带齐 frontmatter 时消费方确实没再断言"已被取代的事实"，但作者自陈"主对照在其自身协议下无效（对照组过多直接拒答）、且要把语料里其它时效线索都剥掉，元数据才显出作用"。
- 第三方 aws-samples 在 BIRD mini_dev 上用 500 个独立 Agent 测得 EX 74.0（测的是"充分性"，另一命题）。
- **结论**：字段方向有效、能减少"拿过期/未核验内容当定论"，但不是银弹，也替代不了人工判断与来源核查；垃圾进仍垃圾出。
